## Build contract

The editor no longer requires a physical audio backend merely to compile. This is
feature separation, not a substitute audio driver or fake pkg-config metadata.

| Cargo features | Purpose | Audio device |
|---|---|---|
| none | Model, project, offline rendering, device-independent transport tests | Never opened |
| `desktop` | Native egui editor and offline export | Not built; UI says unavailable |
| `desktop-audio` | Full desktop, live CPAL transport, Loop/Seek/Follow and exclusive audition | Opened only by explicit Play or Audition |
| `realtime` | Optional host transport/probe binaries, without GUI | Probe/transport opt-in |
| `ui-capture` | `desktop` plus Linux EGL framebuffer validation example | Not built |

`--all-features` includes `realtime`, so it still requires the platform's real audio
development libraries. This cloud environment has no `jack.pc`/ALSA development
metadata. That build and physical device checks remain blocked; no packages,
services, audio settings or user-computer state were changed. Do not use fake
pkg-config files to make such a build appear verified.

## Reproduce

From this project root, use the existing isolated official Rust/Cargo installation:

```sh
export CARGO_HOME="$PWD/.cargo-home" RUSTUP_HOME="$PWD/.toolchain/rustup"
export PATH="$PWD/.cargo-home/bin:$PATH"
scripts/validate_cloud.sh
# Optional actual framebuffer captures; requires working Linux EGL/OpenGL 3.3:
scripts/validate_cloud.sh --capture evidence/NEW-cloud-ui-check
```

The script runs formatting, core and desktop tests, UI-capture all-target Clippy
with warnings denied, and a real native desktop binary build. It checks that the
desktop dependency graph excludes CPAL/ALSA/JACK and that `desktop-audio` retains
CPAL. Logs and SHA-256 source manifests are written to a new evidence directory;
the script fails if source changes while it runs. No network fetching is used.
If a cache is absent, fetch the pinned official sources separately using
`cargo fetch --locked`; do not change dependency versions to bypass the cache.

Use the appropriate build for launch:

```sh
# Editor / offline export; requires an actual X11 or Wayland session to launch:
cargo run --locked --offline --features desktop --bin leviathan
# Full audio application on an appropriately configured host:
cargo run --locked --offline --features desktop-audio --bin leviathan
```

## What framebuffer evidence proves

`examples/ui_capture.rs` uses the installed EGL implementation, glutin's supported
[offscreen device display](https://docs.rs/glutin/0.32.3/glutin/api/egl/display/struct.Display.html#method.with_device),
and egui's production Glow painter to render a real OpenGL pbuffer and read its
pixels. The exact already-locked glutin 0.32.3 package becomes an optional direct
dependency; no package versions or sources change. eframe's version-pinned
`CreationContext::_new_kittest` and `Frame::_new_kittest` supply integration data
without inventing raw window handles.

`shell` and `edit` invoke the real `Leviathan::update`. `edit` seeds actual editor
content through an accessor compiled only with `ui-capture`; it is not a claim
that mouse/keyboard interaction entered those notes. `follow` invokes the real
read-only `playback_view` component at a specified snapshot row, visibly labeled
as an isolated component check. **It does not prove full-app Follow layout or
running transport.** Outputs are rendered at 1180×780 and the supported minimum
900×620 with scale 1. JSON companions record the real GL renderer/version,
dimensions, production-vs-component scene, primitive/color counts and painted
labels. Existing PNG/JSON files are refused, not overwritten.

These captures support visual/layout review of actual code. They do **not** prove
an OS window launched, system keyboard/clipboard/drag-drop integration, display
scaling on the user's monitor, sound audibility, or physical latency. This cloud
has no active X11/Wayland session; full OS integration and current host audio
remain an explicit separate acceptance check.
